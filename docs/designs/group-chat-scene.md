## Problem Statement

텍스트 채팅은 말의 내용만 남기고 관계의 신호는 작은 회색 글씨로 밀어낸다. 누가 지금 방에 있는지, 읽고 답을 안 했는지, 3시간 만에 답했는지, 방을 나갔는지. 단톡방의 드라마는 사실 이 신호들에서 나온다. 유튜브의 "단톡방 실사판" 스킷이 웃긴 이유도 이 신호를 몸짓으로 바꿔 보여주기 때문이다.

제품: 채팅방이 원탁이 되는 메신저. 홈에는 내 아바타(셀카로 만든 페르소나)가 서 있고, 민트색 바텀시트에 채팅방 목록이 있다. 방에 들어가면 친구들이 원탁에 둘러앉아 있는데, **지금 방에 들어와 있는 사람만 고개를 들고** 대화한다. 읽씹, 늦은 답장, 나가기 같은 신호는 자세와 몸짓으로 바뀐다.

해커톤 주제(SCHMIDT · 채팅창 다음의 인터페이스)와의 연결: 말풍선 목록이라는 채팅 UI가 사라지고, 접속 상태와 주의가 공간 속 자세로 보인다.

목표: VC 심사위원 과반이 통과를 눌러 본선 8팀에 들고, 최종적으로 "이 팀과 후속 미팅을 하고 싶다"를 끌어낸다.

## Demand Evidence

- 행동 수준의 수요 증거는 아직 없다. 팀은 이 주제를 30분 만에 골랐고, 심사위원도 그 사실을 감안한다.
- 유튜브 스킷 조회수는 "코미디언 연기를 보고 싶다"는 증거일 뿐 제품 수요의 증거가 아니다.
- 가장 가까운 기존 행동(오늘 검증 안 됨): Gen Z는 단톡 명장면을 스크린샷 찍어 공유하고, Bitmoji·ZEPETO처럼 아바타로 자신을 표현한다.
- 결론: 이번 심사에서 VC가 사는 것은 팀이다. 목표 문장(B+C): "채팅이 숨기던 신호를 자세와 몸짓으로 보여주니까 다 터졌고, 왜 웃긴지 이 팀은 정확히 알더라."

## Status Quo

카톡·iMessage의 "1"/"Read" 표시, 단톡 스크린샷, Memoji/Bitmoji 스티커.

## Target User & Narrowest Wedge

- 제품 타깃: 글로벌 Gen Z 친구 단톡(iMessage 스타일). 데모 대화는 영어이고, 내용은 팀원들의 실제 대화를 옮겨 와서 진짜성을 지킨다.
- 오늘의 실제 사용자: 링크를 혼자 열어보는 VC 심사위원(한국어 기기일 가능성이 높다).
- 가장 작은 단위: 웃긴 단톡 한 방이 친구들 얼굴이 둘러앉은 원탁 장면이 되는 것.

## Constraints

- 12:02 KST 기준. 14:45 코드 동결, 15:15–15:45 제출, **16:15 제출 보류 최종 시각**, 17:00 하드 마감.
- 제출은 딱 1회. VC 과반이 통과를 눌러야 하고, 통과한 팀 중 선착순 8팀이 본선에 간다.
- 제출물: VC가 직접 열어서 써보는 작동 데모 링크 + 설명 PDF 2장. 발표는 본선에서만 한다.
- 무인 심사. 로딩 지연이나 오류가 한 번만 나도 탈락할 수 있다.
- **개발자 2명.** A = 방(원탁) 담당, B = 홈·페르소나·대본·배포·PDF 담당.

## Premises (합의됨)

1. 심사위원은 팀을 산다. 목표 문장은 인사이트와 웃음(B+C)을 하나로 묶는다.
2. 타깃은 글로벌 Gen Z 단톡이다. 데모 대화는 영어로, 내용은 실제 대화에서 가져온다.
3. 핵심 IP는 채팅 신호를 자세와 몸짓으로 옮기는 연출 규칙이다. 특히 "방에 있는 사람만 고개를 든다"는 접속 상태 표현. Sora cameo와의 차별점은 프롬프트가 없다는 것과 텍스트 UI가 버리던 신호를 되살린다는 것이다.
4. 제출은 한 번뿐이다. 일찍 낸 미완성본보다 늦게 낸 완성본이 낫다.
5. 실사형 생성 영상은 쓰지 않는다. 웹 2D 캐릭터 + TTS로 실시간 렌더링한다.

## Approaches Considered

- **A' 셀프 체험형(셀카는 선택 기능, 신호 칩)** — 내가 권장. 사용자는 셀카를 핵심으로 하는 쪽을 골랐다.
- **A+ (채택) = A' + 셀카 페르소나를 핵심 경로로 승격 + 모든 실패에 대비책.** 이후 사용자 UX(홈 아바타, 민트 바텀시트, 원탁 방)로 화면 구조를 바꿨다.
- **B 스크린샷 에피소드 풀버전** — 기각. 무인 심사에서 실패 지점이 너무 많다.
- **C 라이브 무대** — 기각. 비동기 심사에는 실시간 관객이 없다.
- **신호 칩, 대화 붙여넣기** — 이번 제출에서 뺌. 칩은 방 대본과 "내가 보낸 메시지가 읽씹당함"으로 대체했다. 붙여넣기는 iMessage·카톡 데이터에 읽음 정보가 없고 길이 축소·실패 처리가 커서 로드맵으로 옮겼다.

## Recommended Approach

### 화면 구조

1. **홈.** 화면 가운데에 내 아바타가 서 있다(idle 숨쉬기). 처음엔 기본 아바타이고, 아래에 [📸 Make it you] [Pick a stand-in] 버튼이 나란히 있다. 하단에는 민트색 바텀시트가 반쯤 올라와 있고 채팅방 목록이 보인다. 각 항목에는 방 이모지와 이름, 멤버 얼굴 겹쳐 쌓기, 마지막 메시지 미리보기, 안 읽은 수, "지금 고개 든 사람 수"가 표시된다.
2. **방(원탁).** 타원형 원탁을 약간 위에서 내려다보는 시점. 모든 자리(나 포함 최대 5석)는 테이블 먼 쪽 호에 카메라를 향해 앉는다. 그래야 모든 얼굴이 보인다. 내 자리는 민트색 테두리로 표시한다. 방에 없는 사람은 고개를 숙이고 폰을 보는 자세(흐리게)이고, 방에 들어오면 고개를 든다. 하단에 자막과 입력창("Say something…")이 있다.
3. **Cast yourself.** 셀카(카메라 또는 업로드)를 넣으면 카툰 페르소나가 생기고, 홈 아바타와 모든 방의 내 자리가 내 얼굴로 바뀐다. 이름표는 "You".

### VC의 90초 경로

| 시간 | 일어나는 일 | API |
|---|---|---|
| 0~5초 | 홈. 기본 아바타 + 바텀시트. 첫 방 "Friday plans 🍕"에 안 읽음 3 배지와 "Open a chat 👇" 힌트 | 0회 |
| 5~25초 | 첫 방 입장(클릭 = 소리 잠금 해제). 두 명은 고개 들고 대화, 한 명은 고개 숙임. 2~3번째 비트에 펀치라인: Leo가 고개를 들어 👀 쳐다보고(자막 "Read 9:41") 다시 고개를 숙인다 | 0회 |
| 25~45초 | VC가 아무 말이나 입력 → 내 자리 캐릭터가 그 말을 한다 → Maya가 고개를 들어 읽고 다시 숙인다. VC가 읽씹당한다. 두 번째로 보내면 Jun이 💦 화들짝 고개를 든다("sorry I was asleep") | 0회 |
| 45~90초 | 홈으로 돌아가 [📸 Make it you] → 내 얼굴 페르소나 생성(목표 20초 이내) → 방에 다시 들어가면 내 얼굴이 원탁에 앉아 있다 | 1회 |

나머지 방(시간이 되는 만큼): "Family 👨‍👩‍👧"(엄마가 입력하다 멈춤, 아빠의 메시지 취소), "Group project 😩"(한 명이 일어나 의자를 밀고 나감).

### 신호 → 자세·몸짓 규칙 (핵심 IP)

| 신호 | 연기하는 사람 | 몸짓 |
|---|---|---|
| 방에 없음 / 안 보는 중 | 그 사람 | 고개 숙이고 폰 보기, 흐리게 (`head_down`) |
| 방에 들어옴 | 그 사람 | 고개 듦 (`look_up`) |
| 말하기 | 말하는 사람 | 몸 통통 + 말풍선 + TTS (`talk`) |
| 읽고 답 없음 | **답하지 않은 사람** | 고개 들어 말한 사람을 👀 쳐다봄 → 다시 고개 숙임 (`read_ignore`). 퇴장하지 않음 |
| 늦은 답장 | 늦게 답한 사람 | 화들짝 고개 듦 + 💦 + 헐떡 (`startle_up`) |
| 방 나가기 | 나가는 사람 | 일어나 의자 밀고 퇴장, 자리가 빔 (`stand_leave`). 나머지는 `freeze`. 다시 등장하지 않음 |
| 메시지 취소 | 보낸 사람 | 말하다 ✋ 로 입 막음 (`cover_mouth`) |
| 입력하다 멈춤 | 그 사람 | 고개 들고 입 열었다(…) 닫고 다시 숙임 (`typing_stop`) |
| 리액션 | 리액션한 사람 | 🫶 / 😂 (`heart`, `laugh`) |

무대 상태 모델: 각 멤버는 `present`(고개 듦)·`away`(고개 숙임)·`gone`(나감, 빈자리) 중 하나다. 비트가 상태를 바꾼다. `talk`는 `present`일 때만 가능하고, `away`인 사람이 말하는 비트가 오면 렌더러가 먼저 `look_up`을 자동으로 넣는다.

### Architecture

- Next.js (App Router) + TypeScript, Vercel 배포. 화면은 홈 하나와 방 하나(클라이언트 상태로 전환).
- **방 대본은 직접 쓴 데이터**(`src/data/rooms.ts`)다. 대화 → 장면 자동 변환(규칙 엔진)은 로드맵. 방마다 `script`(입장 시 자동 재생)와 `onUserMessage`(내가 보낸 n번째 메시지에 대한 반응 목록)가 있다.
- 렌더러: React + CSS keyframes. 페르소나 PNG를 원형으로 잘라 둥근 몸통 위에 얹는다. `head_down`은 머리 회전·축소 + 폰 화면 빛 + 흐리게.
- **TTS 타이밍:** 대사가 있는 비트는 `utterance.onend`에서 다음으로 넘어가고, `max(1500, 글자수 × 60)ms` 상한 타이머를 같이 건다. `lang='en-US'`로 고정하고 `voiceschanged`를 기다린 뒤 영어 음성을 고른다. 영어 음성이 없거나 `speechSynthesis`가 없으면(인앱 브라우저 등) 같은 타이밍으로 자막만 진행한다. 첫 방 입장 클릭 핸들러 안에서 빈 발화로 iOS TTS를 잠금 해제한다.
- **페르소나:** `/api/persona` → 이미지 생성 API(팀이 **유료 키**를 가진 OpenAI 또는 Google 이미지 모델). 스타일 프롬프트는 **13:00에 동결**하고, 그 뒤 팀 캐스트 페르소나와 프리셋 6개를 같은 프롬프트로 생성한다. 프리셋은 실존 인물이 아니라 텍스트 프롬프트로 만든다. 정적 페르소나는 512px WebP로 줄이고, 프리셋은 Cast yourself를 열 때 지연 로드한다.
- **업로드 처리:** 클라이언트에서 사진을 캔버스로 다시 그려 JPEG(긴 변 1024px 이하, 1MB 이하)로 변환해 보낸다(HEIC·큰 원본 대비). 응답은 축소한 WebP/JPEG. `/api/persona`에 `maxDuration`을 명시한다. 클라이언트 타임아웃은 25초(AbortController).
- **동의 문구(사실대로):** "Sent to {provider} only to draw your cartoon. We don't keep it." 서버 로그와 오류 리포트에 요청 본문·이미지를 남기지 않는다.
- **대비책:** 타임아웃·오류 → "Our artist is busy — pick a stand-in", 카메라 거부·카메라 없음 → "No camera? Pick a stand-in." 둘 다 프리셋 그리드로 간다. `getUserMedia`는 기능 감지 후 사용하고, 없으면 업로드와 스탠드인만 보여준다.
- **남용 방지:** 제공사 대시보드에 지출 상한을 건다(주 방어선). 서버 메모리 rate limit은 IP당 분당 30회로 넉넉하게 두되 최선 노력용이다(서버리스 인스턴스끼리 공유되지 않음, 행사장 Wi-Fi가 한 IP로 묶일 수 있음). 초과하면 스탠드인으로 보낸다.
- **13:00–13:30 측정 규칙:** 배포된 Vercel 환경에서 팀 셀카 10장으로 지연 p50/p90과 성공률을 잰다. p90 > 20초 또는 성공률 < 80%면 더 빠른 모델·낮은 품질·작은 해상도로 바꾼다. 14:00에도 기준 미달이면 셀카 버튼을 숨기고 스탠드인만 낸다.

- 13:30에 원탁이 첫 방 대본을 끝까지 재생 못 하면 → 방은 1개만, 나머지 몸짓은 뺌.

### 제출 게이트와 실패 정책
