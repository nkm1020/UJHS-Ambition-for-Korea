## Problem Statement

텍스트 채팅은 말의 내용만 남기고 관계의 신호는 작은 회색 글씨로 밀어낸다. 읽고 답 안 함, 3시간 뒤 답장, 방 나가기, 메시지 취소, 입력하다 멈춤. 단톡방의 드라마는 사실 이 신호들에서 나온다. 유튜브의 "단톡방 실사판" 스킷이 웃긴 이유도 이 신호를 몸짓으로 바꿔 보여주기 때문이다.

제품: 단톡 대화를 넣으면 각 친구의 페르소나(셀카로 만든 카툰 캐릭터)가 한 무대에 나와 대화를 연기하고, 채팅 메타신호는 정해진 연출 규칙에 따라 몸짓으로 바뀐다.

해커톤 주제(SCHMIDT · 채팅창 다음의 인터페이스)와의 연결: 사용자는 AI와 채팅하지 않는다. 이미 있는 대화가 곧 대본이고, AI는 보이지 않는 감독이다.

목표: VC 심사위원 과반이 통과를 눌러 본선 8팀에 들고, 최종적으로 "이 팀과 후속 미팅을 하고 싶다"를 끌어낸다.

## Demand Evidence

- 행동 수준의 수요 증거는 아직 없다. 팀은 이 주제를 30분 만에 골랐고, 심사위원도 그 사실을 감안한다.
- 유튜브 스킷 조회수는 "코미디언 연기를 보고 싶다"는 증거일 뿐, "내 단톡이 영상이 되길 원한다"는 증거가 아니다.
- 가장 가까운 기존 행동(오늘 검증 안 됨): Gen Z는 단톡 명장면을 스크린샷 찍어 스토리나 다른 방에 공유한다. 문자 대화 스토리 숏폼 장르도 존재한다.
- 결론: 이번 심사에서 VC가 사는 것은 아이디어의 수요가 아니라 팀이다. 목표 문장(B+C): "채팅이 숨기던 신호를 몸짓으로 보여주니까 다 터졌고, 왜 웃긴지 이 팀은 정확히 알더라."

## Status Quo

단톡 스크린샷(정적인 이미지 한 장), Memoji/Bitmoji 스티커, 손으로 편집한 문자 스토리 영상.

## Target User & Narrowest Wedge

- 제품 타깃: 글로벌 Gen Z 친구 단톡(iMessage 스타일). 데모 대화는 영어이고, 내용은 팀원들의 실제 대화를 옮겨 와서 진짜성을 지킨다.
- 오늘의 실제 사용자: 링크를 혼자 열어보는 VC 심사위원. 옆에서 설명해줄 사람이 없다.
- 가장 작은 단위: 웃긴 단톡 한 장면이 친구들 얼굴이 나오는 20초짜리 장면이 되는 것.

## Constraints

- 지금 11:51 KST. 15:00 완성, 15:00~16:00 사이 제출, 17:00 하드 마감. (사용자 추정: 15~16시에 완성하면 본선 진입 가능성 90~95%)
- 제출은 딱 1회. VC 과반이 통과를 눌러야 하고, 통과한 팀 중 선착순 8팀이 본선에 간다.
- 제출물: VC가 직접 열어서 써보는 작동 데모 링크 + 설명 PDF 2장. 발표는 본선에서만 한다.
- 심사는 무인 상태다. 로딩 지연이나 오류가 한 번만 나도 탈락할 수 있다.
- 팀 구성은 아직 모름(질문에 답이 없었음).

## Premises (합의됨)

1. 심사위원은 팀을 산다. 목표 문장은 인사이트와 웃음(B+C)을 하나로 묶는다.
2. 타깃은 글로벌 Gen Z 단톡이다. 데모 대화는 영어로, 내용은 실제 대화에서 가져온다.
3. 핵심 IP는 메타신호를 몸짓으로 옮기는 연출 규칙이다. Sora cameo와의 차별점은 프롬프트가 없다는 것(대화가 대본)과 텍스트 UI가 버리던 신호를 되살린다는 것이다.
4. 제출은 한 번뿐이다. 일찍 낸 미완성본보다 늦게 낸 완성본이 낫다. 15:00 완성, 15:00~16:00 제출.
5. 실사형 생성 영상은 쓰지 않는다. 웹 2D 캐릭터 + TTS로 실시간 렌더링해서 무인 심사에서도 깨지지 않게 한다.

## Approaches Considered

- **A' 셀프 체험형 (셀카는 선택 기능)** — 내가 권장한 안. 사용자는 A+를 골랐다(셀카로 생기는 "어?" 순간을 핵심으로 판단).
- **A 최소 버전** — A+에 흡수됨.
- **B 스크린샷 에피소드 풀버전** — 기각. 스크린샷 파싱, 이미지 생성, 영상 내보내기까지 실패 지점이 너무 많아 무인 심사에서 위험하다.
- **C 라이브 무대** — 기각. 실시간 관객이 있어야 하는데 비동기 심사에는 관객이 없다.

## Recommended Approach: A+ (셀카 페르소나를 핵심에, 대신 모든 실패에 대비책)

### VC의 60초 경로 (이게 곧 제품 스펙)

1. **0~10초 — 첫인상.** 랜딩에는 한 줄 훅과 큰 "▶ Play" 버튼 하나. 미리 만든 샘플 장면이 재생된다. 팀원 페르소나는 미리 생성해 정적 파일로 넣고, 장면 JSON도 미리 만들어 두어 API 호출은 0회다. 핵심 펀치라인(읽씹당한 캐릭터가 쳐다보다 돌아서는 장면)이 8초 안에 나온다. 소리를 꺼도 자막으로 전달된다.
2. **10~30초 — 신호 칩.** 장면 아래에 [Left on read] [Replied 3h later] [Left the chat] [Unsent] [Typing… then nothing] 칩을 둔다. 하나를 누르면 몸짓이 바뀐 장면이 즉시 다시 재생된다. 결정론적 규칙 엔진이라 API 없이 동작한다. VC가 인사이트를 손으로 확인하는 순간이다.
3. **30~60초 — Cast yourself (핵심).** 웹캠으로 셀카를 찍거나 업로드하면 카툰 페르소나가 생성되고(목표 20초 이내, 진행 중 화면에는 재치 있는 문구), 샘플 속 캐릭터 하나를 내 얼굴로 바꿔 다시 재생한다. 내 얼굴이 읽씹당하는 장면이다.
   - 대비책: 25초 타임아웃, 오류, 카메라 거부 중 하나라도 생기면 프리셋 페르소나 6개 중 고르게 한다("Our artist is busy — pick a stand-in"). 어떤 경우에도 막다른 길은 없다.
   - 동의 문구: "Your photo is only used to draw your cartoon. We don't store it." 그리고 실제로 서버는 사진을 메모리에서만 처리한다.
4. **선택 기능 — 내 대화 붙여넣기.** Claude 감독이 처리한다. 20초가 지나면 샘플로 돌아가며 안내 문구를 띄운다. 카톡 내보내기 형식과 iMessage 복사 텍스트를 둘 다 받는다(심사위원이 한국 VC라서).

### 신호 → 몸짓 규칙표 (핵심 IP)

| 신호 | 감지 방법 | 몸짓 |
|---|---|---|
| 읽고 답 없음 | "Read 2:14 PM" / "읽음" 표시 뒤 그 사람의 메시지 없음, 또는 칩 | 쳐다봄 → 돌아섬 → 퇴장 |
| 늦은 답장 | 타임스탬프 간격 1시간 이상, 또는 칩 | 땀 흘리며 뛰어 들어옴, 숨 헐떡임 |
| 방 나가기 | "X left the conversation" / "님이 나갔습니다" | 문 쾅 닫고 퇴장, 남은 사람들 얼어붙음 |
| 메시지 취소 | "X unsent a message" / "삭제된 메시지입니다" | 말하다가 손으로 입 틀어막음 |
| 입력하다 멈춤 | 칩 전용(내보내기 데이터에는 없음) | 입 열었다… 닫고… 시선 피함 |
| 리액션 | "Loved '…'" / "Laughed at '…'" | 하트 손 / 웃다 넘어짐 |
| 연속 메시지(3개 이상) | 같은 사람이 연속으로 보냄 | 말이 빨라지고 한 발 다가옴 |
| 대문자, !!! | 텍스트 패턴 | 소리침, 화면 흔들림 |

원칙: 몸짓은 규칙 엔진이 결정론적으로 고른다. Claude는 자유 형식 텍스트를 스키마로 정규화하고 감정 톤을 붙이는 데만 쓴다. 그래야 심사 중에 결과가 안정적이다.

### Architecture

- Next.js (App Router), Vercel 배포, 단일 페이지.
- 장면 스키마(JSON): `cast[{id, name, personaUrl, voice}]`, `beats[{actorId, line?, action, durationMs, emotion?}]`.
- 규칙 엔진: 정규화된 메시지 목록을 beats로 바꾸는 TS 함수(결정론적). 샘플 장면은 빌드 시점에 미리 계산한 정적 파일.
- 렌더러: React + CSS keyframes(또는 Framer Motion). 3~4명이 서는 무대에 원형으로 자른 페르소나 머리와 단순한 몸통을 둔다. 몸짓은 액션 프리셋으로 만들고, 자막을 띄운다. 목소리는 브라우저 speechSynthesis를 쓰고 캐릭터별로 pitch/rate를 다르게 준다(API 없음). 클릭 이후에만 재생해서 자동재생 차단을 피한다.
- 페르소나: `/api/persona` → 이미지 생성 API(팀이 키를 가진 OpenAI 또는 Google 이미지 모델). 스타일 프롬프트는 고정한다(sticker-style cartoon head, front-facing, plain white background). 클라이언트에서 원형으로 자른다. 사진은 저장하지 않는다.
- 감독: `/api/direct` → Claude(지연을 줄이려 Sonnet 5.5)로 붙여넣은 대화를 메시지와 시스템 이벤트 목록으로 정규화한 뒤 규칙 엔진에 넘긴다.
- 키는 서버에만 둔다. IP당 간단한 rate limit을 걸어 심사 중 키 소진을 막는다.
- 팀원 페르소나는 13:00 전에 미리 생성해서 정적 자산으로 커밋한다.
