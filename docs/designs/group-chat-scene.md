## Problem Statement

텍스트 채팅과 음성 메시지는 내용만 남기고 관계의 신호는 작은 회색 글씨로 밀어낸다. 누가 지금 방에 있는지, 읽고 답을 안 했는지, 3시간 만에 답했는지, 방을 나갔는지. 음성 메시지는 이미 전 세계에서 흔히 쓰이지만, 듣는 경험은 파란 막대기 목록이다. 유튜브의 "단톡방 실사판" 스킷(예: 루키치 "남자들의 단톡방")이 웃긴 이유는 대화를 사람들이 직접 말하고, 신호를 몸짓으로 보여주기 때문이다.

제품: 채팅방이 원탁이 되는 메신저.
- 처음 들어오면 **마이룸**에서 내 캐릭터를 꾸민다.
- 애플 지도처럼 아래에서 끌어올리는 **바텀시트**에 채팅방 현황이 있다.
- 방을 고르면 내 캐릭터가 걸어 들어가 **원탁**에 앉는다. 지금 보고 있는 사람은 **앉아 있고**, 안 보는 사람은 **엎드려 있다.**
- 대화는 TTS가 아니라 **실제 목소리**다. 말하면 내 캐릭터가 그 목소리로 말하고 말풍선이 뜬다.

해커톤 주제(SCHMIDT · 채팅창 다음의 인터페이스)와의 연결: 말풍선 목록과 음성 막대기라는 채팅 UI가 사라지고, 대화는 목소리로, 접속 상태와 주의는 공간 속 자세로 보인다. 타깃은 한국이 아니라 글로벌 시장이다.

목표: VC 심사위원 과반이 통과를 눌러 본선 8팀에 들고, 최종적으로 "이 팀과 후속 미팅을 하고 싶다"를 끌어낸다.

## Demand Evidence

- 행동 수준의 수요 증거는 아직 없다. 팀은 이 주제를 30분 만에 골랐고, 심사위원도 그 사실을 감안한다.
- 유튜브 스킷 조회수는 "코미디언 연기를 보고 싶다"는 증거일 뿐 제품 수요의 증거가 아니다.
- 가장 가까운 기존 행동(오늘 검증 안 됨): 음성 메시지 사용, 단톡 명장면 스크린샷 공유, Bitmoji·ZEPETO 같은 아바타 꾸미기.
- 결론: 이번 심사에서 VC가 사는 것은 팀이다. 목표 문장(B+C): "채팅이 숨기던 신호를 자세와 목소리로 보여주니까 다 터졌고, 왜 웃긴지 이 팀은 정확히 알더라."

## Status Quo

카톡·iMessage의 "1"/"Read" 표시, 음성 메시지 막대기 목록, 단톡 스크린샷, Memoji/Bitmoji.

## Target User & Narrowest Wedge

- 제품 타깃: 글로벌 Gen Z 친구 단톡. 데모 대화는 영어이고, 내용은 팀원들의 실제 대화를 옮겨 와서 팀원 목소리로 녹음한다.
- 오늘의 실제 사용자: 링크를 혼자 열어보는 VC 심사위원(한국어 기기, 한국어로 말할 가능성이 높다).
- 가장 작은 단위: 웃긴 단톡 한 방이 친구들 캐릭터가 둘러앉아 진짜 목소리로 떠드는 원탁 장면이 되는 것.

## Constraints

- 12:12 KST 기준. 14:00 실시간 추가 여부 체크포인트, 14:45 코드 동결, 15:15–15:45 제출, **16:15 제출 보류 최종 시각**, 17:00 하드 마감.
- 제출은 딱 1회. VC 과반이 통과를 눌러야 하고, 통과한 팀 중 선착순 8팀이 본선에 간다.
- 제출물: VC가 직접 열어서 써보는 작동 데모 링크 + 설명 PDF 2장. 발표는 본선에서만 한다.
- 무인 심사. 로딩 지연이나 오류가 한 번만 나도 탈락할 수 있다.
- **개발자 2명.** A = 방(원탁) 담당, B = 마이룸·바텀시트·대본·녹음·배포·PDF 담당.

## Premises (합의됨)

1. 심사위원은 팀을 산다. 목표 문장은 인사이트와 웃음(B+C)을 하나로 묶는다.
2. 타깃은 글로벌 Gen Z 단톡이다. 데모 대화는 영어로, 내용은 실제 대화에서 가져온다.
3. 핵심 IP는 채팅 신호를 자세와 몸짓으로 옮기는 연출 규칙이다. 특히 "보고 있으면 앉아 있고, 안 보면 엎드린다"는 접속 상태 표현. Sora cameo와의 차별점은 프롬프트가 없다는 것과 텍스트 UI가 버리던 신호를 되살린다는 것이다.
4. 제출은 한 번뿐이다. 일찍 낸 미완성본보다 늦게 낸 완성본이 낫다.
5. 실사형 생성 영상은 쓰지 않는다. 웹 2D 캐릭터로 실시간 렌더링한다.

## Approaches Considered

- **A' 셀프 체험형(신호 칩)** — 내가 권장했던 안. 칩은 방 대본과 "내가 보낸 메시지에 대한 반응"으로 대체됐다.
- **A+ 셀카 페르소나 핵심** — D10에서 채택했다가, 사용자 흐름(마이룸 꾸미기)으로 대체. 이미지 생성 API, 동의 문구, 20초 대기, 딥페이크 우려가 함께 사라졌다.
- **B 스크린샷 에피소드 풀버전** — 기각. 무인 심사에서 실패 지점이 너무 많다.
- **C 라이브 무대** — 기각. 비동기 심사에는 실시간 관객이 없다.
- **TTS, 대화 붙여넣기** — 뺌. 목소리는 실제 녹음으로, 붙여넣기는 로드맵으로.
- **실시간 멀티유저 (D12: C 채택)** — 녹음 방 + 내 실제 음성을 먼저 완성하고, 14:00에 앞서 있을 때만 별도 경로로 추가한다.

## Recommended Approach

### 화면 구조

1. **마이룸(첫 화면).** 내 캐릭터가 방 안에 서 있다(idle 숨쉬기). 옆이나 아래에 꾸미기 패널: 피부색, 머리 모양, 머리 색, 눈, 옷 색. 바꾸면 즉시 반영되고 기기에 저장(localStorage)한다. 기본값은 무작위로 정해서 처음부터 귀엽게 보이게 한다.
2. **바텀시트(애플 지도 방식).** 마이룸 하단에 살짝 걸쳐 있다가, 끌어올리면 반 → 전체로 펼쳐진다. 방 카드마다 이모지와 이름, **작은 원탁 미리보기**(앉은 사람과 엎드린 사람이 보임), 마지막 메시지 미리보기, 안 읽은 수가 있다. 첫 방에만 "Open a chat 👆" 힌트.
3. **방(원탁).** 내 캐릭터가 걸어 들어와 빈자리에 앉는다(2초). 보고 있던 친구만 고개를 돌려 쳐다본다. 타원형 원탁을 약간 위에서 내려다보는 시점이고, 모든 자리(나 포함 최대 5석)는 테이블 먼 쪽 호에 카메라를 향해 앉는다. 내 자리는 민트색 테두리. 하단에는 🎤 녹음 버튼과 텍스트 입력창.

### VC의 90초 경로

| 시간 | 일어나는 일 | 서버 호출 |
|---|---|---|
| 0~15초 | 마이룸. 캐릭터를 몇 번 바꿔본다. 바텀시트가 살짝 보이고 첫 방 "Friday plans 🍕"에 안 읽음 3 | 0회 |
| 15~35초 | 첫 방 입장(클릭 = 오디오 잠금 해제). 내 캐릭터가 걸어 들어와 앉는다. Maya는 앉아서 팀원 목소리로 말하고, Jun과 Leo는 엎드려 있다. 2~3번째 비트에 펀치라인: Leo가 일어나 앉아 👀 쳐다보고(자막 "Read 9:41") 다시 엎드린다 | 0회 |
| 35~60초 | VC가 🎤 를 누르고 말한다 → 내 캐릭터가 **VC 목소리**로 말하고 말풍선이 뜬다 → Maya가 듣고는 엎드린다. VC가 읽씹당한다. 두 번째 메시지에는 Jun이 💦 화들짝 일어나 "wait who said that" | 0회 |
| 60~90초 | 홈으로 돌아가 캐릭터를 바꾸거나 방 2를 열어본다 | 0회 |

마이크를 거부했거나, 마이크가 없거나, 인앱 브라우저라 막혔으면 **텍스트 입력**으로 같은 반응이 나온다(말풍선만).

### 신호 → 자세·몸짓 규칙 (핵심 IP)

| 신호 | 연기하는 사람 | 몸짓 (action) |
|---|---|---|
| 보고 있음 | 그 사람 | 앉아 있음 (`watching` 상태) |
| 안 보고 있음 | 그 사람 | 엎드려 있음, 흐리게 (`away` 상태) |
| 방에 들어옴 / 다시 봄 | 그 사람 | 일어나 앉음 (`sit_up`) |
| 안 보게 됨 | 그 사람 | 엎드림 (`slump`) |
| 내가 입장 | 나 | 걸어 들어와 앉음 (`walk_in`), 보고 있던 사람은 고개 돌림 |
| 말하기 | 말하는 사람 | 목소리 재생 + 입 움직임 + 말풍선 (`talk`) |
| 읽고 답 없음 | **답하지 않은 사람** | 일어나 앉아 👀 말한 사람 쳐다봄 → 다시 엎드림 (`read_ignore`) |
| 늦은 답장 | 늦게 답한 사람 | 💦 화들짝 일어나 앉음 (`startle_up`) |
| 방 나가기 | 나가는 사람 | 일어나 의자 밀고 퇴장, 빈자리 (`stand_leave`). 나머지 `freeze`. 재등장 없음 |
| 메시지 취소 | 보낸 사람 | 말하다 ✋ 로 입 막음 (`cover_mouth`) |
| 입력하다 멈춤 | 그 사람 | 일어나 입 열었다(…) 닫고 다시 엎드림 (`typing_stop`) |
| 리액션 | 리액션한 사람 | 🫶 / 😂 (`heart`, `laugh`) |

무대 상태 모델: 각 멤버는 `watching`(앉음)·`away`(엎드림)·`gone`(빈자리) 중 하나다. `away`인 사람이 `talk`를 받으면 렌더러가 먼저 `sit_up`을 넣는다.

### Architecture

- Next.js (App Router) + TypeScript, Vercel 배포. 화면은 마이룸(+바텀시트)과 방 하나(클라이언트 상태로 전환).
- **캐릭터:** 오픈소스 2D 아바타 라이브러리(예: DiceBear의 SVG 스타일 하나) 또는 직접 만든 SVG 레이어. 꾸미기 옵션 값(`AvatarConfig`)으로 얼굴 SVG를 만들고, 몸통은 CSS로 그린다. 스타일 라이선스는 B가 12:30 전에 확인한다. 이미지 생성 API는 쓰지 않는다.
- **바텀시트:** snap point를 지원하는 React 바텀시트 라이브러리(예: `vaul`) 또는 직접 구현.
- **방 대본은 직접 쓴 데이터**(`src/data/rooms.ts`). 대사마다 **팀원이 녹음한 음성 파일**(`public/audio/<room>/<nn>-<name>.mp3`)과 말풍선 텍스트가 있다.
- **재생:** `talk` 비트는 오디오 `ended`에서 다음으로 넘어가고, `길이 + 1000ms`(길이를 모르면 8초) 상한 타이머를 같이 건다. 입 움직임은 Web Audio AnalyserNode 볼륨으로(안 되면 단순 통통 애니메이션). 방 입장 클릭 핸들러 안에서 AudioContext를 resume해 iOS 자동재생 차단을 푼다. 텍스트만 있는 비트는 `max(1500, 글자수 × 60)ms` 동안 말풍선을 보여준다.
- **녹음:** 🎤 탭으로 시작/정지, 최대 15초, MediaRecorder(mimeType은 기능 감지: Chrome `audio/webm`, Safari `audio/mp4`). 마이크 권한은 🎤 를 처음 누를 때만 요청한다. 녹음은 blob URL로 기기 안에서만 재생하고 서버로 보내지 않는다.
- **말풍선 글자(STT):** 브라우저 내장 음성 인식(Web Speech API)이 있으면 녹음과 함께 돌리고, 언어는 `navigator.language`(한국 VC는 한국어로 말할 수 있다). 없거나 실패하거나 녹음과 마이크를 동시에 못 쓰는 기기면 "🎤 0:04" 음성 말풍선으로 대체한다. 13:30–14:00에 Chrome·iPhone Safari·Android Chrome에서 동시 사용을 시험하고, 문제가 있는 기기에서는 STT를 끈다.
- **대비책:** `getUserMedia`·`MediaRecorder`가 없거나 권한 거부 → "No mic? Type instead." 텍스트 입력만. 오디오 파일 로드 실패 → 같은 타이밍으로 말풍선만.
- **실시간 (14:00 체크포인트 통과 시에만):** 별도 경로 `/live/[code]`. 실시간 서비스(예: Supabase Realtime)의 presence로 `document.visibilityState`에 따라 앉음/엎드림을 동기화하고, broadcast로 텍스트 메시지를 주고받는다. 음성은 시간이 남을 때만(Storage 업로드 후 URL 브로드캐스트). 메인 화면에는 "Invite a friend (beta)" 링크 하나만 두고, 14:30까지 두 기기에서 안정적으로 돌지 않으면 링크를 숨긴다.
